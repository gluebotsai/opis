EXECUTIVE SUMMARY
================================================================================

The analytics spec defines 35 certified metrics on conceptual grains:
  campaign_touch, campaign_metric, campaign_performance_fact, ab_test,
  compliance_evaluation, retrospective, campaign_schedule, contact.

The Campaign microservice today stores data in 27 Prisma tables under the
`campaign` schema plus read-only `accounts.*` and `cdp.*`. It does NOT have
separate analytical fact tables. Send-level facts live in:
  - campaign_send_recipients  (closest to "campaign_touch")
  - campaigns.launch_plan.channel_run JSON  (closest to "campaign_metric" for PPC)
  - campaign_contact_engagement + email_suppressions  (unsub / engagement at contact)

RESULT COUNTS (35 metrics in spec):
  FULLY SUPPORTED (as specified)              :  2
  PARTIALLY SUPPORTED (approximation / gap)   : 18
  NOT SUPPORTED (missing data model)          : 15

Overall: Most volume/count metrics and email send ratios are achievable with
mapping and formula adjustments. Financial attribution, retrospectives,
compliance evaluations, PPC lead attribution, and several campaign taxonomy
dimensions are NOT possible without new tables or integrations.

RECOMMENDED MAPPING (if implementing spec on current DB)
================================================================================

1. campaign_touch  :=  campaign_send_recipients
   - touch_id      :=  id
   - occurred_at   :=  COALESCE(updated_at, created_at)
   - delivery_status mapping:
       sent/delivered -> 'delivered' (email: status='sent' after provider accept)
       failed         -> 'failed'
       skipped        -> 'suppressed' IF skip_fail_reason matches suppress list
       pending/queued -> 'queued'
   - response mapping (derive, not stored):
       open_count > 0 OR opened_at IS NOT NULL  -> include 'opened'
       click_count > 0 OR clicked_at IS NOT NULL -> include 'clicked'
       (no converted / engaged / unsubscribed at touch level today)

2. campaign_metric  :=  UNPIVOT campaigns.launch_plan.channel_run
   - metric_type impressions -> impressions
   - metric_type spend       -> spend
   - metric_type conversions -> conversions (PPC only, often synthetic)
   - computed_at             -> campaigns.updated_at or batch scheduled_for

3. live_campaign_count  :=  FILTER status = 'live' (not 'running')

4. open_rate / click_rate  :=  Use existing engagementRates() (unique over
   delivered) — document as intentional deviation from spec's broader open_rate
   numerator.
