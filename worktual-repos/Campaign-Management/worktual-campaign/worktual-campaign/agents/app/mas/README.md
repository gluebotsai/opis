# Campaign MAS package

Three-layer orchestration for **chat** and **Hub** entry:

```text
Super → Domain → Executor → business tools
```

Cron/workers skip Super/Domain and call executors directly via `CRON_BINDINGS`.

## Entry types

| Type | Examples |
|------|----------|
| Chat MAS | contacts, create_campaign, forms, monitoring, WA chat modules |
| Hub MAS | create_contact, on_demand_send, monitoring_report, stop_channel |
| Direct executor | cron events (`template_compliance_scan`, `email_ab_auto_winner`, …) |

Template library inline edit and template coach are **not** SPA chat modules — planned as a separate non-chat flow.

## Package layout

- `super_agent/`: interactive domain routing only.
- `domains/`: one planner/router per product domain.
- `executors/<executor_id>/`: one bounded business-task executor and its `agent.md`.
- `executors/shared/`: native loops reused by multiple Executors.
- `runtime/invoke.py`: common interactive, sticky, Hub, cron and event entry point.
- `runtime/handoffs.py`: structured cross-domain handoffs.
- `runtime/task_memory.py`: session-scoped MAS task state.
- `runtime/tool_adapters.py`: runtime-enforced Executor tool allowlists.
- `runtime/bindings.py`: Hub hints and cron direct-executor targets.
- `runtime/context.py`: shared session + mas_task context for all agent prompts.
- `socket_bridge.py`: SPA module chat → MAS (with legacy rollback when domains disabled).
- `catalog.py`: domain, executor and legacy-module ownership metadata.

## Runtime ownership

- Super routes to a Domain (interactive SPA first turn + Hub unknown intent).
- Domains select Executors via LLM (`invoke_executor`) or deterministic module hints.
- Executors perform business work and emit business UI events.
- Hub bindings are **hints** (`preferred_domain` / `preferred_executor`) — Super still runs.
- Cron/workers use `CRON_BINDINGS` → direct executor (no Super/Domain LLM).
- Sticky SPA follow-ups skip Super (`skip_super` + known domain).
- No regex or phrase matching is used for user-intent routing.

`MAS_ENABLED_DOMAINS=all` is the production default. Set empty and restart for legacy-only rollback.

## Image domain

Flow: **Super → Image Domain → `image_generate` | `image_refine` | `image_attach`**.

Hard rules:

- Raw user chat never reaches Gemini alone — always **ENHANCE_IMAGE_PROMPT** first.
- Unsafe/NSFW requests are refused at enhance (no API call).
- Generated bytes upload to `/api/media`; attach updates template slots when requested.

Env: `GEMINI_API_KEY`, optional `GEMINI_IMAGE_MODEL`. Without a key, generation fails unless `GEMINI_IMAGE_ALLOW_DEV_STUB=true`.

QA: `scripts/qa_image_mas.py`, `tests/test_mas_image_native.py`.
