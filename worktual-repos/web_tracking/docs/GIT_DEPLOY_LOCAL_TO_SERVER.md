# Git push & pull — local development to QA / live server

This guide describes the **end-to-end deploy path** for Web Tracking: edit on your dev machine → sync → commit → push → pull on the server → rebuild services.

It also lists **common git/deploy problems** we have hit (including October 2026) and how to fix them.

**Related:** [DEPLOY_LIVE_SYNC.md](./DEPLOY_LIVE_SYNC.md) (what the sync script copies), [SERVER_DEPLOY.md](./SERVER_DEPLOY.md) (runtime on the host).

---

## 1. Three places to understand

| Location | Role | Git |
|----------|------|-----|
| **Main workspace** (e.g. `cursor_session_sep_8_live/`) | Where Cursor/agents edit code | Often **no** git at root; canonical source of truth for development |
| **`live_web_tracking_folder_2/`** | Nested copy used to **commit & push** to GitHub | Own repo → `Worktual-vibecoding/web_tracking` (`main`) |
| **Server clone** (e.g. `~/Web_tracking_workspace/web_tracking_QA`) | QA or production checkout | `git pull origin main` only — **do not develop here** |

**Rule:** Changes on the dev machine are **not** on the server until you **sync → commit → push → pull → rebuild**.

---

## 2. Ordered workflow (local → server)

### Step 1 — Develop and test locally

- Edit under the **main tree** (`api-node/`, `web/`, `etl/`, etc.).
- Run locally: `python run_backend.py --all` (or your usual ports).
- Verify API + web + ingest.

### Step 2 — Sync main → deploy folder

From **repo root** (parent of `live_web_tracking_folder_2/`):

```bash
bash scripts/sync_main_to_live_web_tracking.sh
```

Optional: copy built SDK into web static (if you changed SDK and serve from `web/public/`):

```bash
cp web/public/webtracking.{min.js,js,esm.js} live_web_tracking_folder_2/web/public/
```

The script:

- Copies `api-node/src`, `web/src`, `etl`, `clickhouse/ddl`, `sdk`, `AI_CHAT`, `shared`, etc.
- **Does not** overwrite live secrets: restores `api-node/src/routes/env.ts` and `AI_CHAT/.env` from **live repo HEAD** after sync.

### Step 3 — Commit and push (dev machine)

```bash
cd live_web_tracking_folder_2

git status
```

**Stage source only** — never commit runtime secrets or bytecode:

```bash
git add api-node web etl sdk shared clickhouse AI_CHAT docs scripts .env.example
git reset HEAD .env AI_CHAT/.env 2>/dev/null || true

# Avoid staging if they appear (see §4)
# __pycache__/, *.pyc, AI_CHAT/logs/, node_modules/
```

```bash
git commit -m "Describe what changed (one line + detail in body if needed)"
git push origin main
```

### Step 4 — Pull on QA / live server

```bash
cd ~/Web_tracking_workspace/web_tracking_QA   # your path
git fetch origin main
```

**If pull is clean:**

```bash
git pull origin main
```

**If pull fails** (local changes, see §4):

```bash
rm -f AI_CHAT/logs/coworker-turn-*.log   # if untracked file blocks merge
git fetch origin main
git reset --hard origin/main
```

Use `reset --hard` on **deploy servers** when you want the box to match GitHub exactly (normal for QA).

### Step 5 — Rebuild and restart on server

```bash
cd api-node
yarn install    # or npm ci — match what you use in prod
yarn build

cd ../web
npm ci
npm run build

cd ..
# Restart api, ingest, AI_CHAT — systemd / pm2 / run_backend.py / your scripts
```

### Step 6 — ClickHouse (only when needed)

- DDL files sync via the script; they are **not** auto-applied.
- Apply only after review and explicit approval:

```bash
python scripts/apply_clickhouse_manual.py clickhouse/ddl/<file>.sql
```

## 3. What to never commit

| Path | Why |
|------|-----|
| `.env`, `AI_CHAT/.env` | Secrets, DB URLs, API keys |
| `node_modules/` | Reinstall on each machine |
| `__pycache__/`, `*.pyc` | Regenerated by Python; cause pull conflicts if tracked |
| `AI_CHAT/logs/*.log` | Runtime logs |
| `.local/logs/`, `.local/pids/` | Local runtime |

Use `git reset HEAD .env AI_CHAT/.env` before every commit in the deploy folder.

## 4. Issues we faced (git push / pull) and fixes

### 4.1 Pull blocked: `__pycache__` / `.pyc` “would be overwritten by merge”

**Symptom (QA server, Oct 2026):**

```
error: Your local changes to the following files would be overwritten by merge:
        AI_CHAT/__pycache__/config.cpython-312.pyc
        ...
        etl/ingest/__pycache__/...
Please commit your changes or stash them before you merge.
```

**Cause:**

- Python rewrote `.pyc` files on the server while services ran.
- Some `.pyc` paths were **still tracked in git** from older commits, so Git treats them as real files to merge.

**Fix on server (QA — match remote):**

```bash
rm -f AI_CHAT/logs/coworker-turn-2026-10-02.log   # if present (see 4.2)
git fetch origin main
git reset --hard origin/main
```

**Prevention (dev repo, one-time cleanup):**

- Ensure `.gitignore` has `__pycache__/` and `*.pyc` (already in repo).
- Remove tracked bytecode from git history going forward:

```bash
cd live_web_tracking_folder_2
git rm -r --cached $(git ls-files '**/__pycache__/**' '*.pyc') 2>/dev/null || true
git commit -m "Stop tracking Python bytecode"
git push origin main
```

- **Do not** `git add` `__pycache__` when committing syncs.

---

### 4.2 Pull blocked: untracked log would be overwritten

**Symptom:**

```
error: The following untracked working tree files would be overwritten by merge:
        AI_CHAT/logs/coworker-turn-2026-10-02.log
```

**Cause:** A log file existed on the server but the incoming commit also adds/updates that path.

**Fix:**

```bash
rm -f AI_CHAT/logs/coworker-turn-2026-10-02.log
# or: mv AI_CHAT/logs/coworker-turn-2026-10-02.log /tmp/
git pull origin main
```

**Prevention:** Do not commit `AI_CHAT/logs/`; keep logs out of git.

---

### 4.3 Local changes to real source (e.g. `api-node/src/routes/visitors.ts`)

**Symptom:** Same “would be overwritten by merge” but for **`.ts` / `.py` source**.

**Cause:** Someone edited code **on the server** instead of push-from-local.

**Fix:**

- **QA should match GitHub:** `git checkout -- path/to/file` or `git reset --hard origin/main`.
- If the server edit was important: copy file aside first (`cp ... /tmp/backup`), pull, then merge manually.

**Prevention:** Treat server as **read-only** for source; all edits → sync → push → pull.

---

### 4.4 Accidentally committing secrets

**Symptom:** `.env` or `AI_CHAT/.env` in `git status` staged.

**Fix before push:**

```bash
git reset HEAD .env AI_CHAT/.env
```

If already pushed: rotate credentials, remove from history (BFG/filter-repo) — ask someone with repo admin access.

**Prevention:** Always run `git reset HEAD .env AI_CHAT/.env` in the commit recipe (Step 3).

---

### 4.5 Pushed code but server still shows old UI/API

**Cause:** Pull succeeded but **no rebuild/restart**; browser cache; wrong service still running.

**Fix:**

- Rebuild `api-node` (`yarn build`) and `web` (`npm run build`).
- Restart api, ingest, web static/nginx.
- Hard refresh browser or check asset hash in `web/dist/`.

---

### 4.6 After pull: API works locally but QA dashboard “Failed to load analytics”

**Cause:** Not always git — e.g. new API route returns 500 (ClickHouse SQL error), and dashboard uses `Promise.all` so **one failed endpoint fails the whole page**.

**Example (Oct 2026):** `/api/analytics/page-dropoff` SQL error until fixed; fixed in source, then re-sync → push → pull.

**Fix:** Check `api.log` on server; fix code locally; repeat sync → push → pull → `yarn build`.

---

### 4.7 `node_modules` copied between machines / yarn errors after pull

**Symptom:** API or web won’t start; yarn/npm resolve errors; paths pointing at another user’s home directory.

**Cause:** Copying `node_modules` from another laptop instead of reinstalling.

**Fix on server after pull:**

```bash
bash scripts/setup_api_node.sh
cd web && rm -rf node_modules && yarn install
cd ../api-node && yarn install && yarn build
```

**Prevention:** Never rsync `node_modules`; always install on each host.

---

### 4.8 Live-only files overwritten by sync

**Symptom:** QA-specific `env.ts` or AI_CHAT `.env` lost after sync on **dev** machine.

**Cause:** Sync script copies main tree over live folder.

**Fix:** Script already runs:

```bash
cd live_web_tracking_folder_2 && git checkout HEAD -- api-node/src/routes/env.ts AI_CHAT/.env
```

Keep **server-specific** env only on the server or in untracked `.env` — not in main sync.

---

### 4.9 Two trees confusion (main vs `live_web_tracking_folder_2`)

**Symptom:** Edits in main workspace; server never updates.

**Cause:** Only `live_web_tracking_folder_2` is pushed to GitHub.

**Fix:** Always run `bash scripts/sync_main_to_live_web_tracking.sh` before commit in `live_web_tracking_folder_2`.

## 5. Quick reference cheat sheet

### Dev machine (happy path)

```bash
# 1. Test locally
# 2. Sync
bash scripts/sync_main_to_live_web_tracking.sh
# 3. Push
cd live_web_tracking_folder_2
git add api-node web etl sdk shared clickhouse AI_CHAT docs scripts .env.example
git reset HEAD .env AI_CHAT/.env 2>/dev/null || true
git commit -m "Your message"
git push origin main
```

### QA / live server (happy path)

```bash
cd ~/Web_tracking_workspace/web_tracking_QA
git pull origin main
cd api-node && yarn install && yarn build
cd ../web && npm ci && npm run build
# restart services
```

### QA / live server (pull stuck)

```bash
rm -f AI_CHAT/logs/coworker-turn-*.log
git fetch origin main
git reset --hard origin/main
# then rebuild + restart
```

## 7. When to ask for help

- Pull conflicts on **real source files** you did not expect on the server.
- Need to apply **ClickHouse DDL** on QA/live (requires explicit approval).
- Secrets were committed or pushed.
- Server git state is unknown (`git status` shows hundreds of modified files) — paste `git status -sb` and whether the host is QA or production before running destructive commands.
