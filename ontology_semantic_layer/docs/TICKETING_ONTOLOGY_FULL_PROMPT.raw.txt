Aliases (spoken words map to type ids)
- Demo, Meeting -> wt:Appointment
- Account, Client, Logo, Prospect -> wt:Customer
- Deal, Opportunity -> wt:Deal
- Help doc, KB -> wt:KnowledgeArticle
- Canned reply -> wt:Macro
- Tenant, Workspace -> wt:Organization
- Case, Issue, Ticket -> wt:Ticket

Types
- wt:Person: Individual human (customer contact or employee).
- wt:Organization: Company or tenant org. Worktual customer-business, not a spoke.
- wt:Customer: Party the tenant does business with. Canonical type for Patient/Client/Buyer.
- wt:Employee: Staff user in the tenant (admin, supervisor, live agent).
- wt:Consent: Permission to process, record, or contact on a scope.
- wt:Channel: Communication medium. Values come from taxonomy.channel.
- wt:Identity: One identifier for a party (cdpId, email, phone, crmId, social).
- wt:CustomerProfile: Unified view assembled from identities and enrich.
- wt:Contact: Named person record in CC contact book (may resolve to Customer).
- wt:ContactDraft: Staged create/update before confirmation. Not an instance of Contact yet.
- wt:ContactSkill: Skill tag on a contact (routing / eligibility).
- wt:KnowledgeArticle: Retrievable org/product/support content. Agents must not invent beyond this.
- wt:OrganizationDirectory: Address, hours, phone, website from get_organization_details.
- wt:Ticket: Support case — customer issue with priority, team, L1 agent and L2…
- wt:SLA: Time commitment (first response or resolution hours by priority).
- wt:TicketNote: Internal or customer-visible note on a ticket.
- wt:TicketDraft: Staged create before confirm. User supplies customer + issue only.
- wt:Team: Staff group that owns a class of tickets; description used by triage…
- wt:KbCategory: Folder for ticketing knowledge articles.
- wt:Macro: Named canned reply for ticket handling.
- wt:TicketPriorityDef: Tenant display name + resolution SLA hours. Instances classify wt:Ticket.
- wt:TicketStatusDef: Tenant display name for lifecycle (Open, Pending, …).
- wt:ProactiveRecommendation: Suggested ticket action awaiting ASGA or human approval.
- wt:AsgaDecision: Safety gate — run now, confirm, recommend only, or reject.
- wt:Anomaly: Metric breach or unusual ops pattern (abandonment, queue depth, SLA).
- wt:PerformanceReport: Generated agent/queue report or chart. Prefer agent names, never raw UUIDs.
- wt:Spoke: Product capability plane. Values include contact_centre, ticketing, crm, campaign, hub.
- wt:Skill: Executable A2A / MCP capability on a spoke.
- wt:HubRequest: spoke-query, run-pipeline, or leftover-work inbound to Hub.
- wt:Strategy: Validated Hub plan with audit ids.
- wt:DispatchAction: Allowlisted work item Hub sends back to a spoke.

Rules
- Counts and rates → ask_semantic with product: ticketing. Ticket lists/rows → SQL tools, not semantic.
- L1 assignee (agent) and L2 resolver are never swapped on reassign_ticket.
- Do not invent customer or ticket facts; CDP + payload + tool results only.
- Writes (create_ticket, macros, KB, teams) require userConfirmed where listed.
- Cross-spoke escalation → spoke_query to hub.orchestrator.
